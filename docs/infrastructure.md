# 语音日记 App — 技术选型记录

> 范围:本目录仅用于讨论技术架构与选型。App 功能仅作为选型参考依据,不在本文档展开。
> 最后更新:2026-05-26(AI 能力栈切换至字节火山引擎)

---

## 一、已确定结论

### 1. 目标平台
- **仅 Android**(用户只用一台 Android 手机)
- 不上架 Google Play,自用 sideload APK 即可,无需开发者账号

### 2. 云厂商划分
采用**双云**:
- **字节火山引擎**:承担 AI 能力栈(ASR + LLM + TTS),单账号、单 API Key
- **阿里云**:承担基础设施(OSS 归档备份、域名、未来如需 ECS),用户已有账号与备案

### 3. 语音识别(ASR)
- **字节豆包录音文件识别 / 实时 ASR**(火山引擎)
- 中文一线、长录音稳定、标点分段强
- 5 分钟连续录音使用**异步录音文件识别**(精度更高、单价更低)
- 放弃 OpenAI Whisper:大陆需代理
- 放弃阿里 Paraformer:两家质量近平,与 LLM/TTS 同源更重要

### 4. LLM
- **字节豆包大模型 Doubao-1.5-pro / 1.6-pro**(火山引擎)
- 主力模型负责反思式追问对话与文本润色
- 轻量任务(打标签、标题生成)可走 `doubao-lite` 档位
- 用途已明确:口语整理为通顺文字、主题总结与打标签、反思式追问对话

### 5. TTS
- **字节豆包语音合成 2.0**(火山引擎)
- 2025-10 发布,中文情感语音合成业界天花板之一
- 支持自然语言指令调情绪,无明显机器腔,适合日记反思朗读场景
- 与 ASR/LLM 同一账号与计费体系

### 6. 数据存储与备份(方案 1)
- **本地 SQLite 作为主存储**(日记文本、元数据、标签等结构化数据)
- **本地文件系统存音频原文件**(m4a)
- **每周自动备份到阿里云 OSS 归档存储**
  - 音频按年估算 2.5 GB,归档存储约 0.0033 元/GB/月
  - 年化总成本 ≈ **5 元/年**
- 备份策略:本地全量打包(SQLite + 音频)→ 加密 → 上传 OSS
- 优势:无服务器运维、隐私最佳、几乎零成本、随时可迁移

### 7. App 形态
- **Flutter 打包 APK** sideload 到 Android 手机
- Dart 3.x + Flutter 稳定版
- 关键插件方向(具体版本在实施阶段定):
  - 录音:`record` 或 `flutter_sound`
  - 本地数据库:`drift`(类型安全 SQLite ORM)或 `sqflite`
  - HTTP:`dio`(豆包 ASR/TTS/LLM API 调用)
  - WebSocket:`web_socket_channel`(TTS 流式)
  - 文件路径:`path_provider`
  - OSS 上传:阿里云 OSS REST API + `dio`(无官方 Dart SDK,自封装)
- 不使用 Play Store,本地 `flutter build apk --release` → ADB 安装

#### 选定依据
1. **保留未来多端可能性**:日记数据具有长期价值,5 年后若想在 iPad / Mac / Web 上查阅,Flutter 一套代码即可扩展,这是 Flutter 在本场景下唯一的硬优势,但够硬
2. **开发体验**:热重载迭代 UI 极快;Dart + Flutter 文档清晰,AI 辅助编程支持充分
3. **生态够用**:录音、SQLite、HTTP/WebSocket 均有成熟插件;阿里云 OSS 无 Dart SDK 但 REST API 简单可自封装
4. **可控的让步**:
   - 包体积 20MB+(自用可忽略)
   - 录音边缘场景可能要写 platform channel(5 分钟前台录音是基础场景,插件足够)
5. **数据格式与框架解耦**:正文走 Markdown 文件,SQLite 仅作索引,即便未来弃用 Flutter 数据仍可平滑迁移

### 8. 备份加密方案
- **阿里云 OSS 服务端加密(SSE-KMS / SSE-OSS)**
- App 端不做额外加密,上传时通过 HTTPS 传输,落盘由 OSS 自动加密
- 推荐 `SSE-OSS`(由 OSS 托管密钥,免费、零运维),无需自建 KMS

#### 选定依据
1. **威胁模型匹配**:主要防"账号被未授权访问导致明文泄漏",而非"防阿里云本身"。SSE 已足够覆盖
2. **零密钥管理负担**:无客户端密钥丢失=数据永久解不开的风险
3. **零成本**:`SSE-OSS` 不额外收费
4. **未来可加强**:若日后引入更敏感内容,可在 App 端再叠一层 AES-256 客户端加密,不影响当前架构

### 9. 备份触发策略
- **主策略:条件触发(自动)** — 通过 Flutter `workmanager` 插件调用 Android WorkManager,在**充电中 + WiFi 联网 + 设备闲置**满足时自动备份,频次以"周"为单位
- **兜底:手动触发** — App 内提供"立即备份"按钮,可随时强制上传
- 备份内容:SQLite 主库文件 + 自上次备份以来新增的音频文件(增量)
- 失败重试由 WorkManager 自带退避策略处理

#### 选定依据
1. **零打扰**:充电+WiFi+闲置三条件天然避开流量/电量/性能影响,完全不感知
2. **可控**:手动按钮兜底,关键时刻(换机/出差前)可强制保险
3. **WorkManager 原生支持**条件约束(Constraints API),无需自己写状态机
4. **Flutter 实现简单**:`workmanager` 插件成熟,Android 侧零额外原生代码

### 10. 数据格式原则
- 日记正文以**纯文本 / Markdown**存放,SQLite 仅做索引和元数据
- 不绑定任何框架/ORM 的私有 schema,确保未来可无痛迁移到任何技术栈

## 三、讨论过程留档

### 3.1 App 形态:原生 vs Flutter

#### 原生 Android(Kotlin + Jetpack Compose)
**优势**
- 录音/音频 API 最完整(`MediaRecorder`、`AudioRecord`、前台服务、音频焦点)
- 系统集成深:桌面小部件、Quick Tile、Tasker 联动等
- 性能、启动速度、包体积(5-10MB)最优
- 文档齐全,AI 辅助编程质量高
- 无抽象层,问题直接查官方文档

**劣势**
- 若无 Kotlin/Compose 经验有学习成本
- 未来想出 iOS/桌面版要重写
- UI 代码比 Flutter 略啰嗦

#### Flutter 打包 APK
**优势**
- 一套代码未来可扩展桌面 / iOS / Web
- 热重载开发体验好
- 录音、SQLite、HTTP 都有成熟插件
- Dart + Flutter 文档清晰

**劣势**
- 隔了一层抽象,原生能力(后台录音、前台服务、特殊权限)依赖插件质量
- 包体积 20MB+
- 音频/录音边缘场景插件覆盖不全,可能要写 platform channel
- Dart 是单一用途语言

#### 决策导向
- 如果**这辈子只在 Android 用** → 原生 Kotlin
- 如果**愿意为未来多端留一手** → Flutter
- 折中:无论选哪个,**数据存储与框架解耦**,迁移成本可控

### 3.2 ASR 方案演进

最初候选:
1. OpenAI Whisper API — 精度最高但需代理
2. Android 原生 `SpeechRecognizer` — 免费但中文与标点较弱
3. 本地模型(whisper.cpp / Vosk) — 离线但集成复杂、资源消耗大
4. 混合(原生 ASR + 云端 LLM 润色)

**结论**:用户最终选择**国内云端 ASR**,避免代理依赖,与 LLM 同源。

### 3.3 AI 三件套(ASR + TTS + LLM)厂商对比

#### 候选厂商横评

| 维度 | 阿里云 (DashScope) | 字节火山 (豆包) | 讯飞 | 腾讯云 | MiniMax | DeepSeek |
|---|---|---|---|---|---|---|
| ASR | Paraformer-v2 顶级 | 豆包 ASR 与 Paraformer 近平 | 老牌但贵 5-50× | 工业级 | 无 | 无 |
| TTS 自然度 | CosyVoice 2,略机械 | **豆包 2.0,中文情感天花板** | 超拟人,被新一代超越 | 中规中矩 | Speech-02,国际榜首但贵 3× 且大陆稳定性次之 | 无 |
| LLM 共情对话 | Qwen 像"助手/班主任" | **Doubao 像"朋友"**,C 端飞轮加持 | 星火,迭代偏慢 | 混元,生态绑微信 | — | 偏理性分析,会"剖析"用户 |
| 综合成本(用户用量) | ~10 元/月 | ~6-8 元/月 | 50+ 元/月 | ~10 元/月 | ~30-50 元/月 | — |
| 账号/SDK 复杂度 | 单账号、HTTP/WS | 单账号、HTTP/WS | Android SDK 最齐 | SDK 完整 | HTTP | HTTP |

#### 用户用量基线
- ASR:月约 5 小时录音
- TTS:月约 5-15 万字符(LLM 反思文本朗读)
- LLM:月约 50 万 input + 20 万 output tokens

#### 三套候选方案

| 方案 | ASR | TTS | LLM | 月成本 | 自然度 | 共情 | 运维 |
|---|---|---|---|---|---|---|---|
| A. 全阿里 | Paraformer | CosyVoice | Qwen-Plus | ~10 元 | 7/10 | 7/10 | ⭐⭐⭐⭐⭐ |
| B. 混搭(阿里 ASR+LLM + 豆包 TTS) | Paraformer | 豆包 2.0 | Qwen-Plus | ~10 元 | 9/10 | 7/10 | ⭐⭐⭐⭐ |
| **C. 全火山(选定)** | **豆包 ASR** | **豆包 2.0** | **Doubao-pro** | **~6-8 元** | **9/10** | **9/10** | **⭐⭐⭐⭐⭐** |

#### 选定方案 C 的决策依据

1. **TTS 是日记 App 的体验命门**:每天朗读反思文本,机器腔会让用户很快放弃。**豆包 TTS 2.0 是当前中文情感 TTS 的天花板**(MiniMax 持平但贵 3× 且大陆稳定性次之)。CosyVoice 2 在最关键维度上是次优,不值得为"同源"妥协这一点。
2. **反思式追问需要"朋友味"而非"助手味"**:豆包模型是 C 端豆包 App 的底层模型,在"不说教、追问、共情"上有真实用户反馈飞轮。Qwen 是好"助手",豆包是好"朋友"——本场景要后者。社区/V2EX/小红书 AI 陪伴类项目反馈一致认可。
3. **价格反而最低**:豆包 LLM 输出 token 比 Qwen-Plus 还便宜;豆包 TTS 按真实字符计费,不像 CosyVoice 中文字符按 2 倍计算。月度估算 6-8 元,远低于 50 元上限。
4. **运维成本与全阿里等价**:全用火山一家也是**单一账号 + 单一 API Key**,工程负担与方案 A 相同。
5. **唯一让步**:火山没有像讯飞那样齐全的 Android SDK,但提供完整 HTTP/WebSocket 协议文档,Kotlin OkHttp 一两天封装即可。值得付出。
6. **基础设施层仍用阿里云**:OSS 归档备份、域名、ICP 备案沿用阿里云账号,AI 能力栈和基础设施栈分别用各自的优势厂商,无冲突。

#### 被否决方案的理由
- **方案 A(全阿里)**:TTS 自然度断层式落后,直接影响每天的使用体验
- **MiniMax**:TTS 虽好但价格 3× 且只有 TTS,单独开账号不划算
- **讯飞**:SDK 最友好但 API 价格贵 5-50×,用户用量下完全没必要
- **DeepSeek**:LLM 便宜强大但反思对话偏理性分析,场景错位
- **Kimi**:长上下文用户用不到,贵

### 3.4 存储方案对比

| 方案 | 月成本 | 国内访问 | 运维负担 | 备注 |
|---|---|---|---|---|
| **本地 SQLite + OSS 归档备份(选定)** | ~0.4 元 | — | 极低 | 自用最优解 |
| Supabase 官方 Free Tier | 0(超量 25 USD/月) | 慢,无大陆节点 | 0 | 国内不适用 |
| 阿里云 ECS 精简自建(Postgres + MinIO + 薄 API) | ~60 元 | 快 | 中 | 杀鸡牛刀 |
| 阿里云 ECS 完整 Supabase 自部署 | ~100 元 | 快 | 高 | 严重过度设计 |
| 阿里云 RDS PG + OSS + ECS | ~100 元 | 快 | 低 | 仍非必要 |

#### Supabase on 阿里云成本拆解(讨论参考)

资源估算用量(自用):

| 项目 | 估算 |
|---|---|
| 日记条数 | 1000 条/年 |
| 文本量 | 2-5 MB/年(可忽略) |
| 音频量 | ~2.5 GB/年(m4a 5 分钟 / 条) |
| API 请求 | < 100 次/天 |
| 出口流量 | < 5 GB/月 |

Supabase 全家桶 docker-compose 实测**最低 2C4G 才稳定**,1C2G 频繁 OOM。

完整自部署成本(华东,包年均摊):
- ECS 2C4G 经济型 e:~70 元/月
- 系统盘 40GB + 数据盘 50GB ESSD Entry:~18 元/月
- 公网带宽(按流量):~5 元/月
- 快照备份:~5 元/月
- **合计 ~100 元/月 ≈ 1200 元/年**

#### Supabase 否决理由
- 实时订阅、RLS、Auth、Edge Functions 在单用户场景均用不上
- 运维 Docker、Postgres 升级、备份恢复是真实的隐性成本
- 自用 1000 条/年的日记,不需要为"未来扩展"提前付出代价

---

### 3.5 隐藏成本说明(讨论参考)

- **ICP 备案**:阿里云大陆 ECS 用域名访问必须备案(免费,7-20 天)。仅用 IP / 非 80,443 端口可绕开。
- **HTTPS 证书**:免费(Let's Encrypt / 阿里云免费 DV)
- **运维时间**:自部署后端的隐性最大成本,选定本地方案后规避
