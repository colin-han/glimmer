💥 任意步骤失败
!
UPDATE 标记为 failed → 通知 UI → 停止 FGS
title="处理失败"，status=failed。UI 列表中显示红色卡片 + 重试按钮

🔄
重试路径：用户点击"重试" → 主 isolate 将条目状态改回 processing → 保存重试参数到 SharedPreferences → 启动 Processing FGS（dataSync） → RetryTaskHandler 从音频文件重新执行 P1~P6。

⚡ 中断恢复策略

Processing FGS 被停止（用户开始新录音）时，根据中断点决定恢复方式：

P1 中断（TOS 上传中）

音频文件未完全上传，tosKey 未获得。
恢复：重新上传整个文件。
（后续可优化：断点续传）

P2 中断（ASR 识别中）

音频已上传到 TOS，ASR 任务已提交。
恢复：已有 tosKey → 生成预签名 URL → 直接查询识别状态，无需重新上传。

P3 中断（LLM 处理中）

ASR 已完成，transcript.json 已写入。
恢复：读取 transcript.json → 直接执行 LLM，无需重新 ASR。

P4~P6 中断

LLM 已完成，llm_result.json 已写入。
恢复：读取 llm_result.json → 直接更新数据库条目为 completed。
